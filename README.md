# watch-bridge

갤럭시의 카카오톡 알림을 **블루투스로 애플워치에 직접** 보낸다.
인터넷, 회사 Wi-Fi, 핫스팟, 워치 요금제가 모두 필요 없다.

```
카톡 알림 -> 갤럭시 앱(알림 읽기, BLE 서버) --BLE--> 워치 앱(BLE 클라이언트) -> 워치 알림
```

## 상태: 시험 단계 (v0.1)

핵심 위험은 **워치 앱이 손목을 내린 뒤에도 블루투스 연결을 유지하느냐**이다.
Apple 개발자 포럼에는 3분 만에 끊겼다는 보고와 몇 시간 유지됐다는 보고가 함께 있다.
그래서 이 버전은 알림 기능과 함께 **생존 시험 도구**(하트비트, 연결 끊김 기록, 유지 모드 선택)를 넣었다.

## 갤럭시 앱

1. GitHub Actions `android` 실행 결과의 `watch-bridge-galaxy-debug-apk` 를 받아 설치한다
   (출처를 알 수 없는 앱 설치 허용 필요).
2. 앱에서 위에서부터 차례로 누른다: 알림 접근 허용 -> 블루투스·알림 권한 -> 배터리 최적화 예외 -> 브리지 시작.
3. 삼성 폰은 설정 > 배터리 > 백그라운드 사용 제한에서 이 앱을 "제한 안 함"으로 둔다.
4. "테스트 메시지 보내기"로 워치에 알림이 가는지 먼저 확인한다.

이 앱에는 `INTERNET` 권한이 없고, 기록에 메시지 내용을 남기지 않는다.

## 워치 앱

Mac이 없으므로 GitHub Actions(macOS)에서 빌드해 TestFlight 로 설치한다. 이 단계는 Apple 개발자 계정
($99/년) 가입 후 진행한다. 지금 워크플로(`watch`)는 서명 없이 컴파일만 확인한다.

## 생존 시험 방법 (워치 앱 설치 후)

1. 워치 앱을 켜고 갤럭시 브리지를 시작하면 "연결됨"이 된다. 처음에는 페어링 확인이 뜬다.
2. "백그라운드 유지"를 **유지 안 함**으로 두고, 손목을 내린 채 10분, 1시간 뒤에 "마지막 하트비트"를 본다.
3. 같은 방식으로 **확장 런타임**, **운동 세션**을 각각 시험하고, 기록 화면의 끊김·재개 시각을 비교한다.
4. 운동 세션은 배터리를 더 쓴다. 시험 중 배터리가 얼마나 줄었는지도 같이 적어 둔다.

```bash
cd android && gradle testDebugUnitTest assembleDebug
```
